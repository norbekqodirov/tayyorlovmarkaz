# BUG AUDIT REPORT - Tayyorlovmarkaz CRM

Below is the list of identified bugs, their severity, description, and status.

| Sahifa | Muammo | Jiddiylik | Holat |
|---|---|---|---|
| Barcha PDF Eksport sahifalari (`CrmFinance`, `CrmBI`, `CrmStudents`, `CrmLeads`, `CrmGroupDetail`) | jsPDF default `helvetica` shriftini ishlatadi, unda o'zbek lotin (`o'`, `g'`) va kirill harflarini yo'q (Unicode qo'llab-quvvatlanmaydi), natijada eksport qilingan PDF hujjatlarda yozuvlar buzilib yoki bo'sh qolib chiqadi. | High | **Fixed (2026-08-05)** — `src/utils/export.ts`/`pdfFont.ts` allaqachon Roboto Unicode shriftini yuklardi, lekin faqat 'normal' variant ro'yxatdan o'tgan edi; jadval sarlavhalari `fontStyle:'bold'` so'raganda standart (Unicode'siz) shriftga qaytib, buzilib chiqardi. `pdfFont.ts`da 'bold'/'italic'/'bolditalic' ham xuddi shu faylga ro'yxatdan o'tkazildi. |
| CrmDashboard & CrmBI | `server/routes/analytics.ts` backend API stats larni `genericDocument` dan (JSON formatda) oladi, lekin `crud.ts` orqali ma'lumotlar to'g'ridan-to'g'ri Prisma modellariga (`Student`, `Lead`, `Transaction`, `Group`) yoziladi. Buning natijasida dashboardda noto'g'ri yoki bo'sh statistika ko'rsatiladi. | Critical | **Fixed (2026-08-05)** — ildiz sabab bundan ham chuqurroq edi: `Attendance.records` va `GroupSchedule.days` Prisma'da JSON-string (`@db.Text`) sifatida saqlanishi kerak edi, lekin `crud.ts` frontend'dan kelgan haqiqiy massivni o'zgarishsiz yozar edi — bu Prisma validatsiya xatosiga olib kelib, **davomat belgilash va dars jadvali yaratishning o'zi ishlamas edi**. `crud.ts`ga `stringifyJsonFields`/`parseJsonFields` qo'shildi. `analytics.ts` endi `genericDocument` o'rniga haqiqiy `Attendance` jadvalidan o'qiydi. |
| CrmFinance & CrmDashboard | Tranzaksiyalar, talabalar va davomatlarni hisoblash butunlay client-side da `.filter().reduce()` orqali amalga oshirilmoqda. Katta hajmdagi ma'lumotlarda brauzerni sekinlashtiradi yoki qotiradi. | Medium | Open (Faza 1.1 da server-side hisobotga o'tkaziladi — katta refaktor, alohida sessiyada qilinishi tavsiya etiladi) |
| CrmGroupDetail | Guruh tafsilotlari komponenti o'ta katta (~39.7KB) va barcha sub-tablarni bitta faylda render qiladi. Bu esa UI sekinlashuviga va kodni o'qish/o'zgartirish qiyinligiga sabab bo'ladi. | Medium | Open (Faza 0.3 da bo'linadi — katta refaktor, alohida sessiyada qilinishi tavsiya etiladi) |
| CrmLeads | Kanban boardda "O'lik Lid" va "Qayta aloqa" vaqti client-side da hisoblanadi va performance ga ta'sir qilishi mumkin. | Low | Open (Faza 0.3 da Kanban optimallashtiriladi) |
| Xodim Face ID davomati (`staffPortal.ts`, `staffAttendance.ts`) | Server ko'pincha UTC vaqt zonasida ishlaydi (TZ sozlanmagan), lekin O'zbekiston UTC+5 — `new Date().toISOString()`/`.toTimeString()`/`.getHours()` orqali check-in/check-out vaqti 5 soatga siljib saqlanardi. | High | **Fixed (2026-08-05)** — `server/utils/timezone.ts` (`Intl.DateTimeFormat` bilan `Asia/Tashkent`) qo'shildi, `staffPortal.ts`/`staffAttendance.ts`da qo'llanildi. Loyihaning boshqa qismlarida (scheduler.ts, analytics.ts, portal.ts) xuddi shu naqsh hali bor — bu alohida vazifa sifatida qayd etildi. |
| `CrmStudentProgress.tsx` ↔ `/api/progress/:id` | Frontend backend javobini noto'g'ri shaklda kutardi: `assessments`/`tests` massiv emas obyekt edi, `attendance.trend` o'rniga `monthlyTrend`, `payments.paid/debt` o'rniga `totalPaid/pendingAmount`, `homework` umuman kelmasdi — natijada sahifaning deyarli barcha bo'limlari bo'sh ko'rinardi. | High | **Fixed (2026-08-05)** — frontend backend javobining haqiqiy shakliga moslashtirildi; `homework` `Assessment.type==='homework'` orqali ajratiladi; baho rang chegaralari 0-100 shkalaga moslashtirildi (avval 1-5 shkala uchun yozilgan edi). |
| `CrmStudentDetail.tsx` "Testlar" tabi | `TestsTab` `GET /api/tests/submissions?studentId=X` ni chaqirardi, lekin bu endpoint serverda umuman yo'q edi (`/:id` route uni "submissions" ID'li test deb tushunib 404 qaytarardi, xato jimgina yutilardi). | Medium | **Fixed (2026-08-05)** — `tests.ts`ga haqiqiy `GET /submissions?studentId=` endpoint qo'shildi (`/:id`dan OLDIN ro'yxatdan o'tkazilgan). |
| `server/routes/backup.ts` va `/api/auth/backup` (UI tugmasi) | Ikkita parallel backup implementatsiyasi bor edi; UI ("Sozlamalar → Backup") aslida `auth.ts`dagi eskiroq endpointni chaqirardi, u qattiq yozilgan `prisma/dev.db` (eski SQLite qoldig'i) faylini yuklardi — Postgres rejimida bo'sh/eski fayl, production SQLite rejimida ham noto'g'ri fayl nomi. | Critical | **Fixed (2026-08-05)** — umumiy `server/services/dbBackup.ts` (`getDbConfig()`) yaratildi; `auth.ts`ning `/backup` va `/stats` (baza hajmi) endpointlari `DATABASE_URL`ni to'g'ri aniqlab, Postgres uchun `pg_dump` oqimini, SQLite uchun haqiqiy fayl nusxasini qaytaradi. |
